Flagship

QTI Assessment Item Pipeline Deployed

District assessment platforms can import standards-tagged question banks in the IMS QTI interoperability format — but almost nobody authors them by hand, because the XML is unforgiving and the tagging is tedious. I built a pipeline that does it programmatically: items are authored once, tagged to standards in a spreadsheet, and compiled by a Python script into a valid QTI 2.2 package ready for platform import.

Author Item bank + tags Assessment items with item-level TEKS & CCRS codes maintained in a CSV
→
Compile Python tagger Script merges items and metadata, generates conformant XML
→
Package QTI 2.2 export Standards-tagged, platform-agnostic assessment package
→
Deploy Platform import Imported into the district assessment platform; process documented & taught to curriculum staff
Implementation finding: during deployment I identified that the platform associates courses at the test level rather than the item level — a structural behavior that affects how grade-level data is attributed when items are shared across courses. Findings like this only surface when you work at the import layer, and they matter for anyone using the platform for cross-campus comparison.

Analytics

Student Outcome Analytics

Every year I run statistical analysis on my own students' outcomes — in Python, with real inference, not dashboard vibes. The analysis identifies which students are within reach of a cut score, whether an intervention's effect is statistically distinguishable from noise, and where achievement patterns diverge from classroom performance. All published work uses aggregate, de-identified data only.
